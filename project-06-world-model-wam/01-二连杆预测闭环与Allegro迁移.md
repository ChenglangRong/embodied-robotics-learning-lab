# 二连杆动作条件预测与闭环控制

先验证模型能否分辨动作的后果，再验证用它选动作能否完成任务。两个实验共用现有 `ArmPhysics`。动作是两维归一化关节速度请求，环境乘以 2 rad/s，再执行限位和力矩保护。一个控制步为 20 ms，包含五个 4 ms 物理子步。成功条件为末端距目标小于 45 mm、关节速度范数小于 0.4 rad/s，两项连续满足五步。

## 动作条件预测如何进入闭环

`state(env)` 提取 `[q1,q2,dq1,dq2]`。冻结岭回归学习 `Δx=f(x,u)`，规划预测为 `x̂_next=x̂+f(x̂,u)`。模型在每条候选分支起点读一次真实状态，后四步把预测状态继续送回。先分清两项观测：`action` 是请求，`applied_rad_s` 是经护栏后的速度参考，实际速度在 `x_next` 的后两项。日志里 `x`、`action`、`x_next` 属于同一次转移。

`branches()` 从同一重置分支出九条指令序列，第三步翻转符号。用同样的真实轨迹比较动作屏蔽模型、正确对齐的动作模型、输入动作循环右移一格的动作模型。错位组保留所有动作幅度，只换时序，便于定位训练表偏一行的问题。训练过的模型来自[动作条件预测记录](outputs/action-pilot-20261127/report.json)，训练重置为 4100–4139。

`choose_plan()` 对每个候选预测五步。九个候选对全五步使用同一个请求，其中包含零、四个单轴和四个对角请求。代价为最终末端距离平方加 `0.003×‖dq_final‖²`。选代价最小的候选，执行第一步，重新测量并规划。两种模型共用这套候选、代价和护栏。屏蔽模型对所有候选打同分，按预设顺序选零，它诊断动作输入是否可辨。DLS 用实时计算的雅可比直接生成连续速度，是有能力的参考。比较 4501 时应把短时预测误差、动作菜单、速度判据与闭环完成分开检查。

## WAM 练习中未来状态在哪里参与

项目中的低维练习采用共享两层网络，输入为当前 11 维观测，输出为未来五个动作和未来五个关节状态增量。每个时间点的后五步来自同一条 DLS 示范，滑窗止于回合终止。位置增量以 0.1 rad 缩放，速度增量以 1 rad/s 缩放。用三套独立初始化，每套配对两组，结构、数据、样本抽法和优化次数相同。

训练损失为 `L_actions + λ L_future`，动作模仿组取 `λ=0`，联合监督取 `λ=0.25`。未来真实状态只在训练损失中使用。推理时两个组都读当前观测、执行输出动作块中的第一条，再读新观测。这里检验训练期未来监督对共享表示和闭环的影响。DreamZero 联合建模未来视频和动作，Fast-WAM 研究训练期视频监督与推理期未来生成能否解耦。[DreamZero](https://dreamzero0.github.io/) · [Fast-WAM](https://arxiv.org/abs/2603.16666v2)

## 编程操作

```powershell
# 从仓库根目录运行。每次使用新的输出目录。
$Py = './project-02-urdf-mujoco-ros2/.venv/Scripts/python.exe'
$P = 'project-06-world-model-wam'
& $Py -m unittest discover -s $P -v
& $Py "$P/closed_loop_lab.py" '.ci-output/wam-mini' --quick --updates 100
& $Py "$P/closed_loop_lab.py" '.ci-output/wam-replay' --verify "$P/outputs/closed-loop-20261128"
& $Py "$P/render_closed_loop.py" "$P/outputs/closed-loop-20261128" '.ci-output/wam-4501.gif' --seed 4501
```

`--quick` 每域只取两个重置，适合确认管线。去掉 `--quick` 与 `--updates 100` 可重新训练完整规模，默认 800 次更新。`--verify` 使用保存权重重新运行物理闭环和预测分支。`expert_windows.npz` 保存窗口初态、观测、请求动作、执行速度、未来状态增量、重置号与起始步。`predictions.json` 保存同初态各动作分支的预测与实际状态。`trajectories.jsonl.gz` 的每一行是完整回合，含成功、越界、超时和全部护栏动作。

个人练习按一个因素做配对。先预测把 `λ` 从 0.25 调到 0.1 对 OOD 胜负的影响。用 `--aux .1` 重训，先在同一验证集读动作误差。训练出新版本后换一组未用的正式测试重置，避免反复用公布结果调参。改码练习选一个函数。在 `test_dls_window_action_timing_and_applied_reference` 增加按窗口起始步核对的断言，或给 `choose_plan()` 添加带零速后缀的候选。后者每个候选应保留相同预测步数，独立记录额外计算量。

## 个人验收

1. 手写出第 2 步预测的状态与动作分别从哪里取，复现一条错位分支并指出第一个差异样本。
2. 指出规划看五步、执行一步的两处代码。播放 4500 和 4501，在原始日志中找出失败是否由位置、速度或持续步数触发。
3. 交自己的断言或单因素修改、运行前预测、配对逐种子结果及一个失败。ID 和 OOD 分别报告，三个模型种子复用了相同的 20 个环境重置。
4. 公开发布证据只登记工具实际运行。个人掌握状态需要上述独立记录。

## 把同一套检验迁移到 Allegro

从已有[Allegro 55 回合轨迹](../project-05-reinforcement-safety/outputs/allegro-20261128/)取字段。`q_ref_rad` 属于该控制区间，`q_rad`、球腕系位姿、`actuator_force_nm` 和接触力采自区间末。组装 `x_t` 时取前一行末状态，`u_t` 取当前行指令，监督用当前行末和后续窗口的状态。第一行需要评估开始前的观测，缺少该状态时从第二行起取窗。`force_world_n` 在课程中属于外部载荷。已知计划载荷可作为单独的仿真条件，未知未来载荷时只喂过去和当前可观测量，保留载荷信息可用性一致的对照。

| 二连杆做法 | Allegro 中对应的设计 |
| --- | --- |
| 比较同态的不同动作 | 在相同球、腕姿、力时序和重置下对比保持、拇指小步闭合与释放。每次从相同准备状态重新跑，保留未选动作的物理分支 |
| 预测关节增量与末端误差 | 预测腕系球心位移、旋转增量和各指承载。用球心侧移越过阈值定义可观测事件，接触点切向滑动需另采相对速度标签 |
| 动作条件、屏蔽、错位对照 | 共享窗口与训练预算。对比位移误差、未来 100 ms 滑移事件召回和误报，另报预警提前量。先按完整回合分割，再按物体、实际接触摩擦或载荷留出 |
| 每步重规划并用 DLS 作基线 | 同时评测固定抓持、已有解析抗滑与预测辅助控制。每步只执行有界拇指修正，检查掉落、峰值侧移、末段回稳、接触力与干预率 |

第一轮只用仿真可读的真值建立上限，再用关节、触觉与姿态估计做传感对照。训练和测试的未来接触、真实姿态与手腕时序要按实际可见性核对。现有 55 回合适合核验日志和阈值，正式训练需新增动作激励、重置及未见物体条件。本轮交付了迁移方案，Allegro 预测模型和闭环提升仍待实验。
