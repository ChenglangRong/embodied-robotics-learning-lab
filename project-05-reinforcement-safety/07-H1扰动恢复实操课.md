# H1双足扰动恢复实操

本课把已经会动的双足站立扩展为**受扰恢复**：先让H1在已标定的站姿上稳住，再在2秒时施加已知推力，比较四种参考生成规则，最后手算踝关节修正并用完整轨迹验收。当前是解析控制工程基线，强化学习训练次数为0；H1行走与步态另设实验。

先看结论：五个留出重置、100案例的实测结果是 `com` 通过25/25、`fixed` 失败25/25（无扰动也约1.4秒后倒）、`com_no_damping` 失败25/25（踝力矩平均21%时间饱和）、`wrong_sign` 失败25/25（平均0.84秒倒）。这个对比就是本课要你能自己复现和解释的证据。

## 本地操作顺序

双击 `open_h1_lab.cmd`。已有项目02环境和项目03固定模型可直接复用。模型固定提交为 `0059d4335f8156206f63a35662313385f7ad6d74`，许可文本保留在项目03的licenses目录。

1. 选 `fixed`、场景 `none`、种子3000000，点“实时3D · 当前选择”。看机器人不加扰动自己往后倒——这是本课第一个反直觉结果。
2. 换成 `com`，同场景同种子重跑。观察质心误差曲线回到±3.5cm内，恢复时间约0.52秒。
3. 选 `strong_front`（2秒时60N、0.2秒前推）。比较 `fixed` 与 `com` 的GIF：前者前0.7秒就倾斜，后者被推后被拉回。
4. 选 `push_left`（120N侧推）与 `push_back`（60N后推），记录姿态、倾角、足地滑移和饱和比例。
5. 最后跑 `com_no_damping` 和 `wrong_sign`，作为两个独立失败对照，读出失败模式和饱和比例。

“载入保存回放与曲线”读取 `outputs/h1-recovery-20261016-r2/demos/`。实时3D支持全部四控制器、五场景和五留出重置；增益输入只作用于实时或新实验。

## 知识卡1 为什么必须先自己搭站姿

Menagerie固定提交里的 `h1.xml` 自带一个默认姿态（骨盆0.98m，髋俯仰-0.4、膝0.8、踝-0.4）。直接用它做实验会得到荒谬结果：这个姿态要求髋到踝的距离约0.906m，而两条0.4m腿最多只能到0.8m，**双脚被压进地板约10cm**，接触求解器会把机器人弹飞。

本课的站姿是离线标定出来的，四个常量写死在 `Config` 里：

| 量 | 值 | 含义 |
| --- | --- | --- |
| `reference_pelvis_z` | 1.06279m | 足底刚好触地时的骨盆高度 |
| `reference_hip` | -0.20rad | 髋俯仰 |
| `reference_knee` | 0.45rad | 膝 |
| `reference_ankle` | -0.25rad | 踝 |

`H1Stand` 会校验这四个值，改一个就直接报错——这不是洁癖，而是防止“姿态变了、对照却还在比”的隐性污染。**能不能自己复算出1.06279这个高度，是本课第一个个人验收点。**

另一个关键量：踝关节角为0时，足底最低点在踝关节下方0.112m。这个数决定了站姿高度，也决定了任何“把骨盆降一点”的直觉都是错的。

## 知识卡2 踝关节力矩的符号要实测，不要靠直觉

人形机器人教材里的踝策略是：质心偏前就跖屈，让压力中心前移、把身体拉回来。H1的踝关节只有一个俯仰自由度，很容易想当然地把“质心误差为正 → 踝参考为正”写成控制律。**实测结论相反。**

在标定站姿上给一个恒定踝参考偏置，测量质心加速度：

| 踝参考偏置 | 质心平均加速度 |
| --- | --- |
| -0.10rad | -0.076m/s² |
| -0.02rad | -0.303m/s² |
| +0.02rad | -0.421m/s² |
| +0.10rad | -0.643m/s² |

线性部分斜率是 **d(a_com)/d(q_ankle) = -2.85 1/s² per rad**：踝参考越负，质心越往前加速。原因是这条腿链的几何与脚掌形状（足底从踝关节向前延伸0.154m、向后只有0.050m），使得踝关节负向旋转时压力中心反而前移，产生向前的力矩。

`h1_recovery.py` 的 `reference_correction()` 因此把修正**正号相加**，而 `wrong_sign` 模式把它取反。本机实测：反号版本约0.8秒后倒，姿态角超过0.55rad。

个人验收点：在面板上把 `--com-rate-gain` 从2.4改成-2.4（或把 `wrong_sign` 对照跑一遍），先写下你的预测，再看轨迹。

## 知识卡3 站姿本身是不稳定的

把固定参考的PD增益调高仍然会倒，原因不是增益不够，而是这个构型的开环平衡点本身不稳定：标定姿态下质心只比踝关节中心靠前约1.6mm，而脚掌前后支撑区间是[-0.050, +0.154]m，质心几乎压在支撑区间后缘上。微小扰动让质心后移，重力矩随即放大偏差。

对开环系统做阶跃测量得到的是正反馈趋势：恒定参考下质心在1秒内从-0.010m漂到-0.178m（对应上表第一行）。**结论：双足站立不能靠“摆得准”，必须闭环。**

## 知识卡4 控制律与两个匹配对照

四个控制器共用模型、关节PD、力矩限幅、推力时序和重置种子，只改参考生成规则：

| 控制器 | 参考生成 | 作用 |
| --- | --- | --- |
| `fixed` | 恒定参考（无反馈） | 受扰前的开环基线 |
| `com` | `Δq_ankle = Kc·e_com + Kr·ė_com` | 主控制器，`Kc=12`、`Kr=2.4` |
| `com_no_damping` | 去掉 `Kr·ė_com` | 阻尼项的单因素消融 |
| `wrong_sign` | 修正取反 | 符号反例 |

其中 `e_com = com_x - support_x - 0.05`，`support_x` 是左右踝关节中点，0.05m是冻结的质心目标偏移量；`filter_alpha=0.15` 的IIR只用于反馈，原始误差始终写入轨迹。

这是“匹配对照”而不是“堆功能”：`com` 与 `com_no_damping` 只差一个速率项，`com` 与 `wrong_sign` 只差一个符号。任何成绩差异都能追到这两个机制上。

## 知识卡5 手算一次踝关节修正

给定一次测量：`e_com = +0.03m`（质心在目标前3cm）、`ė_com = -0.02m/s`。

```
Δq = 12×0.03 + 2.4×(-0.02) = 0.36 - 0.048 = 0.312 rad
q_ankle = -0.25 + 0.312 = +0.062 rad
```

再算一次反向的：`e_com = -0.05m`、`ė_com = +0.10m/s`。

```
Δq = 12×(-0.05) + 2.4×0.10 = -0.60 + 0.24 = -0.36 rad
q_ankle = -0.25 - 0.36 = -0.61 rad
```

第二次的结果会让踝关节力矩接近饱和（±40N·m），这也是“恢复能力有限”的具体来源。把这两组数在CSV里逐帧核对：`com_error_x_m`、`com_rate_x_m_s`、`ankle_correction_rad` 三个字段必须能反推出同一个 `Δq`。**这是本课第二个个人验收点。**

## 知识卡6 推力、终止与判据

推力在 `t=2.0s` 施加，持续0.2秒，方向沿世界坐标，作用于骨盆质心：

| 场景 | 力 | 作用 |
| --- | --- | --- |
| `none` | 0N | 无扰动站立 |
| `push_front` | +40N x | 轻前推 |
| `strong_front` | +60N x | 主前推 |
| `push_back` | -60N x | 后推 |
| `push_left` | +120N y | 侧推 |

十项判据同时满足才算通过：完整跑完300步（6秒）、始终直立（骨盆高度≥0.62m且倾角≤0.55rad）、推后恢复（质心误差与速率回到±0.035m/±0.12m/s）、恢复时间≤2.5秒、末段稳定、足地滑移均值≤0.25m/s、双脚支撑、完整经历推力窗口。

评价窗口从推力时刻开始；“推后最大位移”是相对推前0.5秒平均质心位置的位移，这样站立偏置不会掩盖扰动响应。

## 知识卡7 实测的稳定性边界

冻结前用开发种子测过的边界（写在 [实验记录](实验记录-H1扰动-20261016.md)），冻结后五留出重置的结果在括号里：

| 控制器 | 60N前推 | 80N前推 | 120N侧推 | 140N侧推 | 无扰动 |
| --- | --- | --- | --- | --- | --- |
| `fixed` | 失败 | 失败 | 失败 | 失败 | 失败（稳定复现） |
| `com` | 通过 | 失败（踝力矩饱和） | 5/5通过 | 1/5通过 | 通过 |

冻结实验100案例实际结果：`com` 25/25（平均恢复时间0.52—0.72秒、滑移约8mm/s、最大俯仰0.086rad、饱和比例0.000）；`fixed` 0/25，平均69步（1.38秒）后倒，饱和比例0.000；`com_no_damping` 0/25，饱和比例0.209；`wrong_sign` 0/25，平均42步（0.84秒）后倒，饱和比例0.626。

边界之外还有两个实测结论：去掉速率项后踝关节饱和比例升到约21%，五个场景全部失败；髋关节横滚反馈对侧向误差的影响小于3mm，对侧向失败阈值的影响是0N，所以最终没有任何用例使用它——**双足侧向稳定性在这条腿链上主要来自双脚支撑和踝策略，不是髋横滚**。这是一个负面结论，按原样保留。

## 知识卡8 重置噪声的边界

重置扰动不是越“随机”越好。实测：关节噪声±0.003rad、速度±0.01m/s时，固定参考和反馈控制器都会在反馈启用前就被推翻；把噪声降到±0.001rad、±0.002m/s后，反馈控制器五个种子全部通过。

冻结协议因此使用**小扰动+无预settle**：初始骨盆高度就取标定触地高度，第一控制步双脚即接触。这个选择写进 `protocol.json` 的 `reset_scope`，和代码一致。**能力边界要如实写：本课成绩只支持这组平地小扰动初态，更宽的初态分布是后续实验。**

## 编程实操与个人验收

打开 `h1_recovery.py`，按 `reset → measure → reference_correction → step → assess` 标出坐标系、单位和控制周期。在轨迹里核对一个时刻的质心误差、滤波值、踝修正、关节参考、实际角度与力矩。

个人修改优先选一个增益：

```powershell
# 仓库根目录；已有项目03固定模型，Python路径按安装环境替换。
& ./.venv/Scripts/python.exe project-05-reinforcement-safety/h1_recovery.py --output project-05-reinforcement-safety/outputs/my-h1-001 --com-gain 6 --com-rate-gain 2.4 --seeds 3000010 3000011 3000012 3000013 3000014
& ./.venv/Scripts/python.exe project-05-reinforcement-safety/verify_h1.py project-05-reinforcement-safety/outputs/my-h1-001 --output project-05-reinforcement-safety/outputs/my-h1-verification.json
```

先写下五场景预测（哪些还能过、饱和比例会升还是降），再运行，再对照。新实验目录与公开基线分开；正式个人评测追加新的留出重置，保持判据和预算固定。个人交付沿用[个人实验记录模板](../project-03-robot-platforms/个人实验记录模板.md)。

跨电脑回放时，任务指标按rtol=1e-7、atol=1e-9比较；完整轨迹中的浮点按rtol=1e-7、atol=1e-7比较，离散字段精确比较。

## 迁移到具身智能

双足恢复能力是“失败恢复”阶段的基础证据：推力大小、恢复时间、支撑状态和饱和比例，可以直接作为安全过滤器的触发条件和接管判据。后续H1行走、Allegro抗滑与手内重定向沿用同一套接口、对照和验收流程；高层规划（含GPT类模型）与VLA动作接口分别按实际模型ID、检查点和算力验收，本课实际模型调用次数为0。
