## 2. 知识卡：策略如何控制机器人

### 卡1：一帧观测说明“现在在哪里、还差多少”

策略读入六个数：

`o = [sin(q1), cos(q1), sin(q2), cos(q2), goal_x-x, goal_y-y]`。

四个三角函数表示机械臂姿态，两个误差表示目标方向和距离。角度加整圈后物理姿态相同，正弦/余弦也相同；直接用角度会在周期边界产生数值跳变。本课的末端误差单位为m，三角函数无量纲。

在面板暂停，连续点三次“单步”，抄下每次obs和末端位置。检查后两个数等于“目标减当前位置”。闭卷问题：删除两个目标误差后，同一姿态要去两个目标，策略如何选择？这个题检验输入是否包含完成任务所需的信息。

### 卡2：动作是一个短时执行指令

网络输出 `a = [qdot1, qdot2]`，单位rad/s。环境把每个分量限制到±2 rad/s，再执行：

`q_next = q + 0.02 * clip(a, -2, 2)`。

例如输出 `[0.5, -1]`，这一帧关节分别变化 `[0.01, -0.02]` rad。动作表示速度；位置由连续执行积累得到。`executed_action`保存限幅后的实际动作，`raw_expert_action`保存专家原始请求。

单步题：取CSV相邻两行关节角，核对差值是否等于0.02乘以后一行的执行速度。本课采集数据另外保存动作前的 `pre_q`，自动测试直接核对 `next_q-pre_q`。

### 卡3：专家示范是一组对齐的“输入—答案”

每步执行顺序为“读取动作前obs → 查询DLS专家 → 保存专家标签 → 执行动作 → 保存下一帧obs”。训练目标是专家限幅后的速度。

普通专家采集时，标签 `action` 与实际动作 `executed_action` 相同。DAgger采集时，学习策略控制机械臂，专家给出该状态的纠正标签；下一帧由学习策略实际动作生成。理解这两列的用途，可以防止把学习策略自己的动作误当专家答案。

“收集专家示范”按钮保存四个 `data-*.npz` 与 `expert-episodes.json`。训练/验证/测试/OOD分别120/24/24/24条完整轨迹；全部专家标签保留，失败轨迹的终止原因也保存。本次专家在这些场景全部成功。

### 卡4：训练、验证、测试各自负责什么

训练集用于更新权重与拟合均值、标准差；验证集用于选检查点；测试集与OOD用于训练结束后的评测。一条轨迹的所有帧进入同一划分，相邻帧的高度相关性需要保留在这个边界内。

当前归一化为 `z=(o-mean_train)/std_train`，标准差下限为0.001。DAgger和追加专家分支继续使用初始训练集的归一化统计。用全部数据计算均值、把相邻帧随机分到训练与测试，会把评测信息带入训练处理。

测试案例已经展示过，后续针对这些案例做改进时，这套结果承担教学回归的角色。最终泛化成绩需要在改进方案固定后另建未查看的留出集。五个训练种子共用同一数据与测试集，SD表示训练随机性。

### 卡5：BC怎样学会专家的映射

网络结构为 `6 → 48 → 48 → 2`。隐藏层使用tanh：`h1=tanh(zW0+b0)`，`h2=tanh(h1W1+b1)`；输出为 `a_hat=2(h2W2+b2)`。输出层为线性函数，实际执行限幅由环境完成。

一个batch包含B条示范，损失为：

`L = (1/(2B)) * Σ_i Σ_j (a_hat[i,j]-a_expert[i,j])²`。

这是两维动作每分量的平均平方误差，单位 `(rad/s)²`。梯度指出参数变化对损失的局部影响；反向传播沿网络逐层计算梯度；Adam用梯度的一阶/二阶移动统计调整步长。实现位于 `MLP.loss_grad()` 与 `MLP.update()`，有限差分测试核对解析梯度。

一次update随机抽256行，默认可重复抽样。1600次update表示参数更新1600次；epoch通常表示完整遍历一轮数据，两者需要按实际采样方式解释。程序每200次及阶段首尾记录验证损失，用最低验证动作MSE选择权重。

### 卡6：单步预测与闭环执行分别验证什么

teacher-forced动作MSE：把专家走过的状态交给网络，比较网络输出与专家标签。闭环成功率：让网络独立执行600步以内，读取它自己造成的新状态，最终到达误差需≤1 mm。

例如专家动作为 `[0.5, 0]`，网络给 `[0.52, 0.01]`，单帧变化较小；后续姿态、目标误差和网络输入都会改变。反复反馈后可能进入示范覆盖较弱的状态。目标附近的微小动作偏差也可能造成持续漂移或误差平衡点。

当前可确认“动作MSE下降，闭环成功率较低”。模型拟合精度、近目标速度偏置、学习状态分布变化、动作限幅、验证检查点选择均是待检验原因。要把某一原因写成结论，需要相应日志与单因素对照。[robomimic评测说明](https://robomimic.github.io/docs/tutorials/viewing_results.html)也区分训练指标与rollout结果。

### 卡7：DAgger把专家标签采到策略访问的状态

本课执行一次DAgger：冻结基础BC → 在16个新训练场景中运行BC → 每5步查询一次专家 → 聚合原示范与新标签 → 追加1200次训练更新。专家查询只产生训练标签，运行轨迹由BC动作推进。

原始DAgger框架围绕策略访问分布收集专家反馈；它的理论结论依赖假设。本课采用一次稀疏查询、纯学习策略rollout的教学变体，结果通过独立闭环实验衡量。[DAgger原论文](https://arxiv.org/abs/1011.0686)

三个追加分支都有相同更新步数与batch大小：同数据追加训练、新专家轨迹、DAgger。后两个分支新增标签数量逐种子完全相同；采集环境步数和壁钟成本分别记录。新专家轨迹的最后一条可能因标注预算截断，账本显式记录 `budget_truncated`。
