# 项目 01：从零操作、阅读、实验和演示

这个项目是一台“数学二连杆”。程序按关节速度改变关节角，再用正运动学计算末端轨迹。你能用它把公式、控制循环、实验日志连起来。当前它没有重力、惯量、碰撞或真实执行器，物理仿真在项目 02 引入。

## B. 用一条流程读懂代码

阅读顺序：`scripts/run_demo.py` 的 `main()` → `run_episode()` → `reset()` → `dls_action()` → `step()` → `save_run()`。每读一个函数，回答“输入是什么、输出是什么、单位是什么”。

```text
seed, goal, Config
   ↓ reset：抽取初始关节角 q
observe：q、目标、末端位置
   ↓ dls_action：末端误差 → 期望末端速度 → 原始关节速度
step：逐关节限速 → q_next=q+dt*qdot → 计算误差与终止
   ↓ 重复
save_run：逐步 CSV + 摘要 JSON + 配置 JSON + 路径 PNG
```

`Config` 定义模型和控制参数。`link_lengths=(0.6,0.4)` 的总伸展半径为 `1.0 m`；`dt=0.02` 表示一次更新推进 20 ms 的**模拟时间**；`max_steps=600` 给出最长 12 s 模拟时间；`tolerance=1e-3` 表示末端距离目标 1 mm 内判成功。

`reset(seed)` 用种子生成初始 `q`。种子固定，初始状态固定。`observe()` 返回关节角、目标、末端位置的副本，防止外部代码意外改写内部状态。

`dls_action()` 先计算 `e=goal-position`，再给出 `v=gain*e`，最后通过雅可比计算关节速度。代码在 `step()` 中逐关节裁剪命令并更新 `q`。`step()` 的返回值为 `(observation, reward, done, info)`；本项目的 `reward=-error` 用作接口示例，成功判据由 `error<=tolerance` 决定。

`run_episode()` 是控制循环：一次执行就是一条轨迹。`trajectory.csv` 的一行代表**执行完一步后的状态**。`q1/q2` 用 rad，`x/y` 和 `error` 用 m，`applied_qdot1/2` 用 rad/s，`time_s` 是模拟时间。`summary.json` 中 `geometric_reachable` 只根据目标离原点的距离和两根连杆的长度判断；`termination=max_steps` 表示循环走到上限，具体成因还要结合几何界、限幅和轨迹判断。

## C. 三种情景观察：先预测，再运行

| 实验 | 相对 `reachable` 的设置 | 运行前预测 | 重点核查 |
| --- | --- | --- | --- |
| `reachable` | 默认目标 `(0.55,0.55) m`，最大 600 步 | 应能达到 1 mm 容差 | `success`、步数、前期是否限速 |
| `unreachable` | 目标 `(1.05,0) m`，最大 300 步 | 目标超过 `L1+L2=1.0 m`，至少差 0.05 m | `geometric_reachable=false`、`geometric_error_lower_bound≈0.05 m` |
| `speed_limited` | 速度上限 `0.05 rad/s`，最大 180 步 | 在这个限速和步数的联合条件下，末端运动受限 | `clipped_fraction`、最终误差、`time_s` |

参考环境的一次运行：可达组 90 步成功、最终误差约 `0.000965 m`；不可达组 300 步走完、最终误差约 `0.0500 m`；速度限幅组 180 步走完、最终误差约 `0.5510 m`。这些数值依赖当前代码、依赖版本与参数；你的运行以本机输出为准。

这三组适合观察不同现象。`speed_limited` 同时改变了速度上限与最大步数，因此其失败结论只适用于这组联合条件。检验速度上限的单因素影响时，固定种子、目标、`max_steps=600` 和其余控制参数，只改变速度上限：

```powershell
.\.venv\Scripts\python.exe scripts\run_demo.py --seed 7 --goal-x 0.55 --goal-y 0.55 --velocity-limit 2.0 --output outputs\control-v2
.\.venv\Scripts\python.exe scripts\run_demo.py --seed 7 --goal-x 0.55 --goal-y 0.55 --velocity-limit 0.05 --output outputs\control-v005
```

两组均使用 `run_demo.py` 的默认 600 步上限。先写下对 `success`、步数和最终误差的预测，再对照两份 `run_config.json` 与 `trajectory.csv`；限速可能改变初期运动方向，检查前几步误差即可验证。

观察细节：可达组的前几步误差可能先升后降。局部雅可比近似、强限速和初始姿态共同决定了实际末端路径。用 `trajectory.csv` 前十行验证这个现象，避免凭路径图直接判控制器错误。
